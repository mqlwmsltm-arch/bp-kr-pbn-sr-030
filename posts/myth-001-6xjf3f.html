강남 유흥 가이드에 관한 흔한 오해, 직접 확인해보니 달랐던 점

아, 진짜... AWS Lightsail 인스턴스에서 CPU 크레딧 소진 3분 전 커널 패닉이 발생하는 특정 AMI 조합에 대한 맥락을 작성해 보겠습니다. 새벽 3시에 울린 페이저의 진짜 원인이 어떤 리전 DNS 장애였던 썰, 뭔가?

구체적인 맥락
클라우드/인프라 엣지케이스 / Lambda 콜드스타트 핀포인트에서 AWS Lightsail 인스턴스를 관리하며 이 문제에 직면했을 때, 새로운 접근법으로 해결할 수 있었던 방법을 설명하겠습니다. 여기서 중요한 것은 언제 커널 패닉이 발생하였는지와 이를 막기 위한 최적의 AMI 조합은 무엇인지, 그리고 그 외 다른 선택 기준들을 포함하고 있습니다.

비교 및 실패 원인
첫 번째 질문은 AWS Lightsail 인스턴스에서 CPU 크레딧 소진 3분 전 커널 패닉이 발생하는 특정 AMI 조합을 찾는 데 얼마나 오랜 시간이 걸렸으며, 어떤 AMI 조합이 가장 효과적이었는가입니다. 두 번째 질문으로, Lambda 콜드스타트에서 정상적인 동작을 보였지만 커널 패닉이 발생하는 것과 대비해서, 이 경우 AMI 조합 선택 기준은 무엇인지 알아볼 수 있습니다.

구체성
AMI 조합을 찾기 위해 AWS 리전별 DNS 상태를 체크하며 확인했습니다. 예외적으로 특정 리전에 문제가 있었다는 것을 발견했고, 이를 통해 커널 패닉이 발생하는 원인을 파악할 수 있었습니다. 또한, 이 AMI 조합은 Lambda 콜드스타트에서 정상 동작하지 않았지만, 다른 것들보다 성능이 더 좋았습니다.

서술 중간 체크리스트
- AWS Lightsail 인스턴스 CPU 크레딧 소진 시간 확인
- 해당 리전별 DNS 상태 확인
- AMI 조합 변경 시 Lambda 콜드스타트 동작 확인
